## Confirmed defects

### SYS-BUG-01 — S2: manual fallback has no editable form before a successful extraction

Owner: Obidit. TC-017/036; SYS-09; BR-023. Root: [manual-form.tsx:144](../../../src/app/(parent)/intake/form/manual-form.tsx#L144), [draft-store.ts:70](../../../src/lib/intake/draft-store.ts#L70).

Reproduction without any mocked API or provider:

1. Open `/intake` in a fresh browser context and acknowledge the notice.
2. Click “ফর্ম খুলুন” / “Open the form” before extracting anything.
3. `/intake/form` displays “এই ডিভাইসে যাচাই করার মতো খসড়া নেই।” and a link back. There are no editable fields.

A second reproduction types synthetic text and injects the canonical E-023/HTTP 429 envelope on the first extract response. After explicitly waiting for the manual-fallback heading, clicking its form link produces the same dead end; the promised retained text is unavailable on that page. The E-023 test injects the response at the browser HTTP seam; it does not claim a live-provider or real budget-exhaustion run. Existing DB cap/refusal tests pass independently.

Cause: `handTo()` sends a valid text-only handoff with `response: null`. `ManualFormScreen` selects `createDeviceDraft(handoff)` instead of `emptyManualDraft()`. The constructor returns `null` when no extraction response exists, so the screen loses both its editable form and its text display. A direct cold visit/reload of `/intake/form` takes the blank-form branch and is a workaround, but does not preserve the lost handoff text.

Expected fix: construct a device-local manual draft from the handoff's source text when extraction failed or was never attempted; keep all unstated fields unknown, preserve any already-attempted submission safely, and retain review-before-submit. Add browser regressions for direct manual navigation, initial E-013/E-023, and text retention.

Evidence: `browser-probes.spec.ts.txt`, `browser-probes.log`, `manual-direct.png`, `fallback-e023.png` in the artifact directory. The final six exploratory browser checks contain two failures for this single root cause. The E-023 case was also repeated after adding an explicit wait for the fallback state; the direct-manual case independently fails without response injection.

### SYS-BUG-02 — S1: verification audit cannot identify the affected officer

Owner: Sadman. BR-010 / audit traceability. Root: [verify.ts:81](../../../src/server/admin/verify.ts#L81).

Verify two different initially unverified synthetic officers as the same admin. Both writes succeed, but audit records have identical subject projections: actor, action, null case/candidate FKs and `{api, verified, target_role}`. The target officer UUID appears in neither subject column nor details. Different timestamps, audit row IDs and request correlation IDs do not identify the changed account. Production request logs retain API IDs rather than the target URL path.

The real restricted-role DB regression expects the two audit subjects to differ and fails. The existing admin tests accept this omission. Proposed fix: persist a safe target-user UUID in an approved audit field, with the required frozen-contract/allowlist review; do not put names or other payload into audit details.

### SYS-BUG-03 — S1: duplicate audit cannot distinguish links sharing one endpoint

Owner: Masnun. BR-010/021. Root: [decision.ts:191](../../../src/server/duplicates/decision.ts#L191).

Create profile links A–B and A–C with A the lower UUID in both. Have the same verified officer dismiss both. Both audit records carry only A, A's reference, the same status/rule and `reason_recorded: true`. Neither the link ID nor B/C is recorded. The source comment claiming recovery from `case_a + status` is false when multiple links share that combination.

The restricted-role DB regression compares these two subjects and fails. Proposed fix: store the safe duplicate-link UUID through the audit allowlist and test shared-endpoint links. Both reports must remain independently visible.

### SYS-BUG-04 — S3: repeat runner rejects absolute config paths

Owner: Sadman / rehearsal tooling. Root: [run-automated-repeats.mjs:241](../../../scripts/rehearsal/run-automated-repeats.mjs#L241).

`npm run rehearsal:automated -- --runs 5 --config /tmp/fera-system-offline.config.ts` exits 2 with `missing config`, although that file exists and Playwright itself accepts it. The preflight uses `join(REPO_ROOT, CONFIG)`, which prepends the repository path to an absolute argument. The repository-relative path to the same file works; five runs then passed. Proposed fix: resolve the supplied path correctly, with CLI regression coverage. This does not block the default config.

### SYS-BUG-05 — S3: lint traverses nested worktrees and fails on unrelated code

Owner: Sadman / CI tooling. Root: [eslint.config.mjs](../../../eslint.config.mjs).

The actual `npm run lint` command exits 1 with 7,044 errors and 69,788 warnings because the flat-config global ignores omit `.worktrees/**`. This checkout contains many historical agent worktrees under that directory, including generated and vendored code. Clean CI can pass while the documented local command fails. The raw compressed output is `lint.log.gz` in the artifact directory. The active-tree-only diagnostic rerun is recorded separately and does not turn the original command into a pass. Proposed fix: exclude the nested worktree tree or keep all lanes outside the lint root.
