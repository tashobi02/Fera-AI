## 2. Route flow

1. Define API-001 with defineRoute. The shared layer checks same-origin on state-changing requests, resolves the principal, applies rate limits and validates the response DTO. The parent cookie is created on the first API call; API-001 permits parent missing intake and staff/officer own found intake. (obidit-spec002/src/app/api/_shared/compose.ts:240-256,279-302; obidit-spec002/src/app/api/_shared/index.ts:68-74; obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:279-283; obidit-spec002/docs/spec/D3_App_Flow_V2.md:303,317)
2. Before any provider dispatch, require the parent to have seen and acknowledged the COMP-050 provider notice. D3 places the notice on S-001; D4 specifies its wording; the multipart fields schema has no notice field. The signal and how the server verifies it are therefore an OD, with request-level acknowledgment and session-level acknowledgment as candidate mechanisms. Do not dispatch when the signal is absent. (obidit-spec002/docs/spec/D3_App_Flow_V2.md:54,300; obidit-spec002/docs/spec/D4_Design_Brief_V2.md:281-287; obidit-spec002/src/contracts/schemas.ts:203-213; obidit-spend-counters/src/server/spend/README.md:5)
3. In the handler, call readMultipart, then parse transcribeFieldsSchema. The shared reader caps the full multipart request at audioMaxBytes plus 16 KiB; also check the audio part itself against LIMITS.audioMaxBytes. Reject malformed content/fields as E-001, oversized audio as E-008, and invalid verified duration as E-009. The error ID for an unsupported codec is UNKNOWN in the API-001 contract and needs a decision; do not label it E-009 without approval. Client duration_s is a hint; server verification is required. (obidit-spec002/src/app/api/_shared/request.ts:164-182; obidit-spec002/src/contracts/schemas.ts:203-225; obidit-spec002/src/contracts/primitives.ts:110-117; obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:79,283; obidit-spec002/docs/spec/D1_PRD_V2.md:515)
4. Verify any supplied draft token against the server principal, kind, expiry and revision. For a new audio intake, the proposed route creates an intake_drafts metadata row before reservation so the call is bound to a server-owned per-draft counter. The row contains no audio, transcript or CaseDraft. The API response requires draft_id and draft_token; the pack does not explicitly say who signs or creates the row. (obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:282-283,1253-1254; obidit-spec002/db/schema_v2.sql:75-87; obidit-spend-counters/src/server/spend/README.md:5-7)
5. Check request abort before reservation. Look up the demo-safe cache before provider dispatch. Proposed accounting: on a cache hit, return the stored synthetic result with cached=true and do not call runPaidCall because there is no provider dispatch; on a miss, continue to the STT adapter. The pack requires visible cache labeling and says misses go live or unavailable, while the six-call rule is expressly for dispatched calls. Whether a hit changes any other call/revision metric remains an OD. (obidit-spend-counters/src/server/spend/README.md:5,9; obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:182,193,284; obidit-spec002/specs/002-intake-ai/spec.md:71-82,108-109)
6. On each actual STT provider attempt, use the A1 SttDispatch seam whose route wrapper calls runPaidCall with apiId API-001, draftId, expectedRevision and a server-owned upper-cost estimate; each retry/fallback is its own runPaidCall invocation. The call estimate uses estimateUpperUsd with a server-owned priceId and the verified billable duration; provider identity/rates are UNKNOWN pending TASK-003. A timeout must be no more than 25,000 ms. (_orchestration/A1-worker.md:22-29; obidit-spend-counters/src/server/spend/README.md:3,7-12; obidit-spend-counters/src/server/spend/service.ts:17-19; obidit-spend-counters/src/server/spend/price-sheet.ts:24-34; obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:182,283,1322; obidit-spec002/docs/spec/D2_TRD_PartB_V2.md:157)
7. Treat every runPaidCall reservation as one dispatched-call increment and one revision increment. reserve_ai_call already increments ai_calls_used and revision atomically. Use expectedRevision (the ReservationRequest property), capture the resulting reservation.revision on success or PaidCallError, and sign the next token from that actual revision. An intentional retry/fallback uses that advanced revision. Do not manually add another revision or hard-code revision 2. (obidit-spend-counters/src/server/spend/service.ts:17-19,123-132; obidit-spend-counters/src/server/spend/paid-call.ts:22-32,120-149; obidit-spend-counters/src/server/spend/README.md:10-12; obidit-spec002/db/schema_v2.sql:544-553; _orchestration/agy-G4b.md:4,14)
8. Return the strict TranscribeResponse on success: transcript, verified duration, language, cached, draft_id, draft_token and ai_calls_used. The transcript remains editable on-device. Do not persist audio or transcript. API-001's failure DTO does not currently specify how to return the metadata draft ID/token after a consumed failed dispatch; decide and test that separately. (obidit-spec002/src/contracts/schemas.ts:217-226; obidit-spec002/docs/spec/D2_TRD_PartA_V2.md:282; obidit-spec002/docs/spec/D2_TRD_PartB_V2.md:77-80; _orchestration/agy-G4b.md:7)

## 3. Pre-submit state

The rule is: “Only principal/expiry/hash/counter/budget metadata reaches the DB; outside providers process synthetic intake after a notice.” The server draft row contains principal binding, kind, expiry, payload hash, ai_calls_used and revision; reservations/cost metadata are separate. Audio is in-memory/in-transit only, and the transcript/CaseDraft stays on the device until review and submit.
