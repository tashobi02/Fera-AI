# LLM extraction adapter — TASK-013 / COMP-007

Server-only module for synthetic intake. Import `createLlmAdapter` from `@/server/ai`. No provider SDK, account configuration, persistence, cache, network client or real provider is included. The fake providers live in `tests/ai/fakes/` and use `[MOCK]` names. TASK-003's providers, models, accounts, prices and terms remain **UNKNOWN**.

## Caller contract

`extract({ kind, sourceText, normalisedText, nowIso }, { signal? })` accepts D5 §6's `ExtractInput`. The caller records the clock explicitly. The adapter recomputes `normaliseText(sourceText)` and rejects a mismatched normalised string with E-001 before dispatch. It never trusts a supplied offset map. Input, source text and the known fields remain in memory for this call only.

The provider receives a frozen request with temperature `0`, an empty tools list, separate system/user messages, prompt version/hash/review status and a repair flag. Providers return strict JSON (an object or JSON string) matching D5's `ExtractOutput`; extra keys are invalid. `name_latin`, `district_code`, draft tokens, revisions, missing-field questions and lifecycle decisions are outside this provider contract. The returned draft sets the two deterministic additions to null. TASK-020 supplies the orchestration and missing fields / templated `NextQuestion` / API-002 envelope; the provider never writes these.

Every non-null fact is checked independently against the frozen field validator and `EvidenceSpan`. A malformed/missing span drops its field. Structurally invalid output triggers the retry/fallback sequence, but independently checked partial fields can still be returned on the manual path. A successful fallback is authoritative for that extraction: its nulls are never filled from earlier invalid responses.

## Evidence and supported grammar

Provider spans must reference **raw `sourceText` UTF-16 positions**, as D2A §2.1 and D5 require. The adapter maps those boundaries into the normaliser's offset map and round-trips through `evidenceForRange`, refusing partial graphemes, surrogate pairs, conjuncts and join-control units. It also refuses spans cutting a letter/mark/number/underscore token, including numeric units. It preserves the raw quote and raw offsets. A normalised-text span is not silently reinterpreted as a raw span. Direct values compare after NFC, including the normaliser's U+09DF expansion; ASCII digit/phone/time derivations are recomputed. The provider's derivation label grants no authority.

Quote presence alone does not establish a field's value. Current support is deliberately narrow (OD-013-4):

- **Allowlist (OD-013-10; lead decisions 2026-10-16, fix rounds 3–6):** the checker accepts only strict known-good shapes; recall is traded for never guessing. Clause = text between `,` `।` `;` `.` (unless a dot exception) and newline. Sentence = text bounded by `।`, `!`, `?`, `？`, `…`, newline, and `.` (unless a dot exception). Dot exceptions: a `.` is NOT a delimiter when between digits, after an abbreviation token (`approx`, `ca`, `c`, `prob`, `est`, `abt`, `আনু`, `not`, `dr`, `mr`, `mrs`, `ms`, `st`), or when not followed by whitespace (e.g. `১০.হয়তো`).
- **Forward-scope qualifier rule (user decision 2026-10-16):** a fact becomes unknown (drop reason `uncertain`) when its **own sentence**, or **any later sentence** in the same text, contains a hedge, negation, or correction token, or a question delimiter (`?`, `？`, `…`). Qualifiers appearing only in an earlier sentence do not taint a later fact (e.g. "পোশাক নিয়ে নিশ্চিত না। বয়স ১০।" keeps age 10). Trailing questions in later sentences ("১১?") and standalone later `?`, `？`, or `…` count as uncertain. When a fact's **own sentence contains no field label** (an age or height anchored only by its unit, a bare time phrase, or a kin-only sex clause such as "আমার ছেলে"), qualifiers in the **immediately previous sentence** also drop the fact to unknown (e.g. "বয়স সম্ভবত\n১০ বছর", "সম্ভবত\nগতকাল বিকেলে", "ঠিক জানি না\nআমার ছেলে" yield unknown). Previous-sentence punctuation is preserved even when separated by spaces, and own-field labels are compared in NFC. Trailing `?`, fullwidth `？`, and `…` right after a fact's value or delimiter, as well as slash alternatives between numbers (`১০/১১`), count as uncertain.
- **Whole-text retraction rule:** if any sentence contains a whole-text reference (`উপরের`, `নিচের`, `পরের`, `সব তথ্য`, `সবকিছু`, `above`, `below`, `following`, `what follows`, `all of this`, `everything`, `any of the above`) together with a hedge, negation, or correction token, the entire text is marked uncertain.
- **Qualifier token lists:**
  - Hedges: বা, অথবা, কিংবা, নাকি, সম্ভবত, বোধহয়, বোধ হয়, মনে হয়, মনে হচ্ছে, হতে পারে, নিশ্চিত না/নই, জানি না, ঠিক জানি না, প্রায়, আনুমানিক, আনু, আন্দাজ, মতো, মত, হয়তো, হবে, শিওর না, sure না, ধারণা, or, maybe, may be, probably, prob, perhaps, likely, approximately, approx, ca, c, est, abt, roughly, about, around, guess, think, might, unsure, uncertain, not sure, possibly, believe, certain.
  - Negations: no, not, never, না, নয়, নই, নেই (`phone no` label is exempt; words like `Nothing` do not match whole negation tokens).
  - Corrections: মানে, actually, sorry, I mean, I meant, না না, আসলে, দুঃখিত, ভুল, ভুল বললাম, ভুলে, ভুলভাবে, ভুলই (ভুল as prefix with suffixes -ে, -ভাবে, -ই; name ভুলু excluded), নাহ, wait, oops, correction, শুধরে, scratch that, my mistake, rather. They count anywhere in a sentence, not only as the first token.
- Text facts require a whole `label value` clause (optionally prefixed by `[MOCK]`), with no attribution text before the label. They must equal both the whole quote and the complete labelled source value (to the next clause delimiter) after NFC or deterministic digit conversion. Labels: name/নাম; clothing/পোশাক/পরনে; marks/চিহ্ন; place/স্থান; district/জেলা; thana/থানা; circumstances/description/বিবরণ; relation/সম্পর্ক. A name comes only from the নাম/name label and contains only letter/mark words, joiners and name separators (spaces, apostrophes, hyphens), with no numeric characters or repeated name label; ছেলে/মেয়ে are never a name source. Conflicting repeated labelled values are unknown.
- Ages and heights: the whole clause must be `[label] number [unit] [old|বয়সী|বয়স]` and nothing else (labels age/বয়স, height/উচ্চতা; units years/yrs/বছর, cm/সেমি/সেন্টিমিটার; Bangla or ASCII digits). Height **must** have an explicit unit (cm/সেমি/সেন্টিমিটার); unitless heights (e.g. "উচ্চতা ৪৮", "height 50") are unknown. Comparators, ranges, `~`, `≥`, "and above", extra words after the unit etc. are unknown. age_min/age_max accept only the range shape `lo-hi`. Repeated contradictory numeric claims are dropped. Fractional ages, string ages, or out-of-range numbers drop per-field as `type_mismatch` in `checkOutput` without invalidating the response structure.
- Sex requires a complete clause: literal male/boy/female/girl/other (optionally labelled sex/লিঙ্গ), possessive আমার/my/our/আমাদের followed by ছেলে/মেয়ে/boy/girl, or possessive kin word directly followed by a single name word (letters only, no digits, e.g. "আমার ছেলে রাফি" gives male, "আমার মেয়ে মিম" gives female). **Kin guard:** if the word after the kin word is a relationship noun (জামাই, বউ, বৌ, স্বামী, স্ত্রী, বন্ধু, friend, boyfriend, girlfriend, husband, wife, in-law, শাশুড়ি, শ্বশুর, ননদ, দেবর, ভাবি, নাতি, নাতনি, চাচা, মামা, খালা, ফুপু, bf, gf, plus possessive inflections -এর / -য়ের / -র), sex stays unknown (e.g. "আমার মেয়ে শাশুড়ি", "আমার মেয়ে নাতি", "আমার ছেলে চাচা", "আমার মেয়ে জামাইয়ের" yield unknown). Conflicting recognised sex words remain unknown. Unknown sex needs no evidence.
- Phones require a whole phone/phone no/number/ফোন/নম্বর + value clause and must equal `normalisePhone`'s value for a complete source claim. The full source is scanned for competing labelled phone claims. Time fields require the normaliser's supported relative/ISO time grammar; narrative clauses starting with a valid time phrase (e.g. "গতকাল বিকেলে মাদ্রাসা থেকে ফেরেনি", BLOCK 4) extract the time interval for the time phrase. The source scan validates matches with that normaliser. Competing canonical phones/intervals are unknown even if the provider omits one. Equivalent spellings do not conflict. All supplied time components must describe the same supported interval; `at_approx` is recomputed, not trusted.
- Verbatim D6 TC-002 text yields sex male, age 13, event time yesterday afternoon interval, and phone number; name stays unknown per OD-013-11 label policy (OD-013-13). Qualifiers in the same sentence still drop TC-002 shapes to unknown. Verbatim D6 TC-002 text is verified at the adapter level with scripted `[MOCK]` providers only; the TC-002 UI, latency, notice and real-provider parts are not verified.
- **Unresolved semantic ownership (OD-013-11):** whole labelled values such as `নাম: রাফির বাবা করিম` and `name: Rafi is missing`, or attribution inherited across clauses (`বাবার তথ্য; নাম: করিম`, `বড় ভাইয়ের তথ্য; বয়স ১৫`), still pass the literal shape. This is an accepted residual risk pending S-003 display mitigation (showing the parent's FULL source text beside every pre-filled field).
- This is a conservative lexical check, not a Bangla/English semantic verifier. Unlabelled descriptions, paraphrases and grammar outside the allowlist need manual completion; recall is not measured.

All returned drafts pass `caseDraftSchema`. Evidence for null/unknown fields is removed. No fact is inferred from another unsupported field. Caller/manual edits and deterministic district/romanisation integration belong to TASK-020 and TASK-012/TASK-009, rather than the provider.

## Dispatch, failure and cancellation

`createLlmAdapter({ primary, fallback, dispatch, log? })` **requires** a `ProviderDispatch` (branded: build it with `brandProviderDispatch`, so a bare `provider.extract` pass-through does not type-check). There is no default bypass to `provider.extract`. TASK-020 must put the provider-notice check and `runPaidCall` inside the function it brands. TASK-020 must plug TASK-063's `runPaidCall` into this seam for **every** dispatch. Its provider callback must forward the signal and reserve/settle the retry and fallback separately. No spend module is imported here. A cancellation/timeout does not establish zero usage: the paid wrapper must retain uncertain reservations until reconciled (D2A §2.1). The wrapper must check the signal before sending a provider request.

Sequence: primary once; one primary repair retry only for structurally invalid output; then one fallback if no success. An outage or timeout goes straight to the fallback. There is no fallback retry. Each attempt uses the same original input; repair adds a separately hashed, fixed instruction without echoing untrusted provider output. Prompt text is a local proposed template, marked `needs_review` (OD-013-1), rather than a pack-supplied verbatim prompt.

The timeout is **25,000 ms**, from D2 Part B §13, E-014. It currently applies per dispatch, including the reservation seam (scope needs review, OD-013-2). The signal is forwarded and a race enforces the deadline even when an implementation ignores abort. Timers/listeners are removed; a late reply cannot change the result. A caller abort rejects with a fixed `AbortError`, never the caller's reason, and stops all retries/fallbacks.

When no provider succeeds:

| Failures | Result |
|---|---|
| Two or more invalid outputs, or the last response is invalid | E-012 |
| Otherwise at least one timed-out dispatch | E-014 |
| Otherwise providers unavailable | E-013 |
| Typed `DispatchRefused("E-019" / "E-023")` from the wrapper | Same ID, stop immediately |
| Invalid caller input/map | E-001, no dispatch, null draft |
| Bug in the output check | E-012, no further paid call, `cause` kept (class only logged) |

Mixed failure precedence is a proposed policy (OD-013-3); homogeneous mappings come from the pack. Only a typed `ProviderFailure` (and a timeout) is an outage; any other dispatch throw is a bug: logged as `unexpected` (class and code only) but still E-013 with the manual form. Messages, stacks and provider text are never inspected or logged. Error classes come from fixed built-in/adapter classes, and codes from a fixed diagnostic allowlist; arbitrary token-shaped error names/codes are dropped. Metadata accessors are never executed, and status must be an integer from 100 to 599.

Failures return `{ ok: false, error: ErrorEnvelope, draft }` with original source and checked partials for a manual handoff. Conflicting partial facts stay unknown. This does not implement SCREEN-005 or claim TC-017's two-second UI acceptance. TASK-020 must preserve its own previously parsed/reviewed device draft and route the result to that form. Failed E-013/E-014 results also carry a non-contract `failure: "unavailable" | "unexpected" | "timeout"` so TASK-020 can tell an outage from a bug.

Every result carries `dropped: {field, reason}[]` (reason: type_mismatch, span_mismatch, uncertain, conflict) for facts the provider asserted but the checks refused; fields it never extracted are absent. Failures always carry a class-name `cause` (no payload).

`log` receives `ai.attempt` entries (slot, attempt, latency, `outcome` incl. `aborted`, error ID, error class/code/status, `reason`, `dropped`), one `ai.summary` with the outcome tally, and `ai.input_rejected` (E-001 reason). Names, messages, quotes, prompts, phones and source text never reach it. The default sink is the project logger (`createLogger`, redaction applies). A broken sink emits only a fixed `ai.log_failed` line (with the error class) to stderr and never repeats a paid call.

Wrappers must not turn bugs into `ProviderFailure` (only a real provider/network failure is one); pass the original error as `new ProviderFailure(status, { cause })` and the adapter logs the cause's class only. `brandProviderDispatch` is for the TASK-020 route wrapper only. TASK-020 must never log or serialise `cause` or `dropped` values. In production lines the outcome is the first `issues` entry (`ok`, `invalid_<reason>`, ...); drop reasons are logged as counts (`{code: reason, path: "n"}`), never field names or values. An abort after a paid attempt still emits `ai.summary` with an `aborted` tally.
