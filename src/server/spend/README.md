# Paid calls — TASK-063

Server-only entry point: `@/server/spend`. TASK-013/014/020 must use `runPaidCall` once per provider dispatch, including each retry and fallback. No providers or routes are wired by this task.

**Route obligations (TASK-014/020, OD-063-7).** This module cannot see the provider notice, the draft token or how drafts are created, so the API-001/002/007 routes must, before calling `runPaidCall`: (a) refuse to dispatch any paid call until the provider notice has been shown and acknowledged (no dispatch before the notice); (b) verify the signed draft token and take `draftId`/`expectedRevision` only from it, bound to the same session or user; (c) check the request's `AbortSignal` and stop before calling `runPaidCall` if the client has gone, because the reservation is retained once made; (d) prevent re-creating drafts to reset the six-call counter (TC-043), e.g. by rate-limiting or bounding draft creation per session/user. None of these is enforced here.

1. The route validates input, resolves the server principal, checks the provider notice and verifies the opaque draft token. Take `draftId` and `expectedRevision` from that token; keep the same revision for every replay of the same client request. Never fetch a newer revision to make a replay succeed. Draft creation and token signing belong to TASK-014/020.
2. Use `estimateUpperUsd` with an injected server-owned price sheet and enforced maximum billable input/output tokens or audio seconds. It returns a branded `UpperUsdEstimate`, required by reservations; a raw decimal string cannot satisfy that type. Rates, model/provider identities, minimum charges and rounding rules must come from TASK-003's `docs/costs.md`. There is no runtime price loader yet. `UNKNOWN_PRICE_SHEET` refuses with E-023. The brand is type-level only: an `as` cast can forge an estimate or sheet, and nothing checks it at runtime. Price sheets are built only by the TASK-003 loader; routes must never construct one. Never accept an estimate or price sheet from an HTTP client.
3. Call `runPaidCall(principal, { apiId, draftId, expectedRevision, upperUsd }, dispatch, { timeoutMs })` with the actual caller's `apiId` (`API-001`, `API-002` or `API-007`). The adapter supplies an integer timeout from 1 through 25,000 ms: D2A COMP-006 specifies speech 25 s → E-014, and D2B §13's E-014 row specifies 25 s for AI operations. D2A COMP-007 provides no different LLM timeout. There is no invented default. `dispatch({ signal })` must perform exactly one bounded call, honour abort and return `{ value, actualUsd }`. USD values are decimal strings with at most six fractional digits, matching the SQL ledger. `null` means billing is UNKNOWN.
4. An unlocked owner/kind pre-check keeps foreign/random draft IDs out of the global budget lock. The SQL reservation then checks expiry, six-call and global caps, locks budget then draft, and advances the revision. The wrapper rechecks owner/kind and the advanced revision while those locks remain held. A stale revision rolls back the entire reservation. COMMIT precedes dispatch; no provider work runs in the transaction. `canCall(apiId)` and `canIntake` bind permissions/kind. The requested paid-call guard also refuses an unverified officer with E-003; the frozen general intake helper still permits such an officer as staff.
5. On success or failure, valid known actual cost within the estimate settles through `settle_ai_call`. A known unbilled failure uses `new PaidProviderFailure("E-013", "0")`; a billed invalid output may use E-012 with its actual cost. Generic failures and timeouts retain their upper-bound reservation. They never restore a draft call slot. The timeout aborts the signal; late results/failures are logged and never settled automatically, even when late billing is known.
6. Successful results return the paid `value` with `settlement: "settled"`, `"retained"` (unknown billing) or `"unsettled"` (bad actual cost or settlement failure). A settlement failure never discards a successful paid output. `PaidCallError` preserves the provider's original E-012/E-013/E-014 ID, and its `failureSource` distinguishes `"provider"` from `"settlement"`. Both results and errors carry the internal reservation metadata. An intentional server retry/fallback uses that advanced revision and makes a new reservation. There is no automatic dispatch retry.

`reservePaidCall` is available for server-internal reservation work. `settlePaidCall` is internal to the service/paid-call implementation and is omitted from the public barrel. Tests import the internal service to verify SQL idempotency: repeating the same settlement amount is safe; a different amount is refused by SQL. A reservation is a trusted server handle, not a client-facing DTO. Do not expose raw handles or additional error properties through a route; use the frozen contract projection/envelope. No adapter bypass of `runPaidCall` is needed by this task.

Server-input faults (a bad `timeoutMs`, upper bound, draft ID, revision, API ID or settlement amount supplied by an adapter) are not the parent's fields: they map to E-013 (`manual_form`) and log `spend.bad_input` with field paths only. A null principal stays E-002 and a disallowed one E-003. Only the module's own IDs (E-002, E-003, E-012, E-013, E-014, E-023) leave the transaction wrapper; any other `ApiError` (for example E-005 from the case helper at the constraints/COMMIT stage) becomes E-013 and logs `spend.error_remapped`.

Logs use the shared allowlist logger: `spend.settled`, `spend.retained`, `spend.late_result`, `spend.late_failure`, `spend.refused`, `spend.bad_input`, `spend.error_remapped`, `spend.commit_uncertain`, `spend.price_sheet_invalid`. Facts are `route` (API ID), `reservation_id`, `draft_id`, `upper_usd` and `actual_usd` (exact decimal strings), `provider_error_id`, `price_id`, a `reason` (`timeout`, `unknown_billing`, `bad_actual`, `settle_failed`), and `describeError` class/code/frame. `log.ts` validates each field (OD-063-8) and drops anything else; no provider text or payload is logged.

Database/price/limit failures fail closed for paid work. E-023 and E-013 retain the contract's `fallback: "manual_form"`. The wrapper never receives or stores a device draft, transcript or audio, creates a case, or changes submission state. Device values remain with the caller. The real case service's reviewed manual submit works after both budget and six-call refusal (DB tests); opening SCREEN-005 remains TASK-020/025 integration.

Commit loss, process death after reservation, an ignored abort, and unknown provider billing can leave a consumed slot and reserved budget. Do not release these automatically. A later known identical settlement is safe; reconciliation policy is UNKNOWN and there is no reaper. The existing draft FK also prevents deleting metadata with reservations; schema-owner cleanup work is recorded as OD-063-6. Replay-key/error-ID/price-sheet/reconciliation decisions and acceptance limits are in [the evidence file](../../../docs/execution/evidence/intake-spend-counters.md).
