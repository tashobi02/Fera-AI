## What is here

```
submission/demo/
├── README.md          — this file
├── run.sh             — orchestrate → capture → postprocess → verify
├── orchestrate.mjs    — DB reset + build + server + capture orchestration
├── capture.mjs        — Playwright Chromium real browser, real Next app
├── postprocess.mjs    — ffmpeg → final.mp4 (105s ±0.1, 1280x720)
├── verify.mjs         — ffprobe + file + provenance checks
├── final.mp4          — 105-second MP4 deliverable (committed, after `run.sh`)
├── captions.srt       — caption manifest (committed, after `run.sh`)
├── proof/             — 8 curated per-beat PNGs (committed, after `run.sh`)
├── provenance.json    — git SHA, beat names, file SHA-256 hashes (committed)
├── raw/               — raw intermediates (NOT committed; gitignored)
│   ├── capture.webm   — raw Playwright recording
│   ├── proof/*.png    — 11 raw per-beat screenshots (uncurated)
│   ├── capture-meta.json
│   └── actors.json
└── .gitignore         — ignores raw/ only
```

Note: there is intentionally **no** sibling `playwright.config.ts` for the
demo. The orchestrator spawns the server, runs the capture, and tears it
down — Playwright's `webServer` lifecycle would re-run the testDir or
require a stub config that does not exist in the project.

## How to reproduce

```bash
# From the repository root, after npm ci and npm run model:fetch
bash submission/demo/run.sh
```

The orchestrator pins `FERA_MODEL_CACHE` to a portable default of
`<repo>/.cache/models` (or honours an absolute override via env). The
server is killed in a `try/finally` so a readiness failure never leaks a
zombie process.

Guardrails (all enforced inside the scripts):

- **Loopback DB only.** `scripts/db/guard.mjs` refuses non-loopback
  `FERA_DB_ADMIN_URL`. The demo uses the per-run
  `fera_e2e_demo_<pid>_<hex>` name validated by `assertDatabaseName()`.
- **No paid provider calls.** `FERA_MODEL_CACHE` defaults to
  `<repo>/.cache/models`; override with an absolute path to an offline
  cache. `DEMO_MODE=1` is exported.
- **No env files read.** `AUTH_SECRET`, `PARENT_COOKIE_KEY`,
  `DRAFT_SIGNING_KEY` are generated per-run via
  `randomBytes(32).toString("base64")`.
- **Port collision-free.** `FERA_E2E_PORT=3115` (overrides the
  tests/e2e default of 3100) so the regular Playwright run is unaffected.

## Captions

`captions.srt` is generated by `postprocess.mjs` from the actual beat
times recorded in `raw/capture-meta.json`. Each beat's `tMs` is scaled by
`ptsFactor = TARGET_DURATION / rawDuration` so the caption windows line
up with the slowed/hold-edited UI. The persistent label plus every caption
says the demo is synthetic and timing-edited; reviewers can grep the
SRT. No voice is recorded; no microphone is touched.

The last 8 seconds of the video are an explicit editorial card stating
that **no release metrics were measured** and **Round 2 is NOT submitted**.

## Provenance

- `provenance.json` records the source `git rev-parse HEAD`, the per-beat
  name list, the SHA-256 hash of `final.mp4`, and the SHA-256 + byte
  length of every curated proof PNG. It is checked into the repo.
- `raw/capture-meta.json` is the source of beat timings (NOT committed —
  it is in `raw/` and is reproducible from the same capture run).
- `proof/*.png` (8 curated frames, committed) are the screenshots the
  postprocess step selected from the 11 raw frames; they are independent
  of the .webm so a reviewer can confirm the journey without re-running
  the capture.
- The `actors.json` file (which holds synthetic officer credentials) is
  in `raw/` and gitignored.
- `tests/e2e/parent-journey.spec.ts` and
  `tests/e2e/officer-lifecycle.spec.ts` are the canonical journeys;
  `capture.mjs` duplicates the same `seedActors` shape and uses the same
  selectors (form fields, role names, dialog buttons) as those specs.
  The video is a visual, not a behavioural substitute. The capture
  script is a `.mjs` file so the TS build surface is not touched.

## What is NOT here

- No voice recording (the prompt says "NO voice capture claim typed/manual
  only").
- No production URL. The video never visits a non-loopback host.
- No freeze / "completion" claims. The closing card states the demo is
  DRAFT pending release G4/G5 and the editorial card explicitly says no
  release metrics were measured and Round 2 is not submitted.
- No human-labels / human audio / human devices. The video is screen + UI
  only.
- No full unit-test sweep. `verify.mjs` is the deliverable check; the
  existing e2e suite owns the journeys.

## Re-running the regular e2e suite

`bash submission/demo/run.sh` does **not** touch the test suite. To run
the regular Playwright run:

```bash
npm run test:e2e
```

It boots on `FERA_E2E_PORT=3100` (the default) and does not read any
files under `submission/demo/`.

The recorded scenario explicitly changes from the parent’s own report to a seeded officer candidate. The capture requires successful API decisions and coordination closure, then shows separate district counts. Raw recordings and ephemeral fixture credentials stay under the ignored raw directory. The verified 105-second MP4 includes an eight-second editorial card; app footage is slowed for readability and is not a latency measurement.
